# Collaboration and Delivery

Use for stakeholder alignment, critique, workshops, handoff, launch, and
decision quality.

## Stakeholder Translation

Translate requests into objectives.

"Add 12 signup fields"
→ qualification / compliance / routing need

"Remove all setup"
→ activation / speed need

"Use the existing component only"
→ engineering / system consistency need

Once objectives are visible, alternatives become negotiable.

## Decision Meeting Format

1. Decision to make
2. User / product context
3. Evidence
4. Constraints
5. Options
6. Trade-offs
7. Recommendation
8. Disagreement / unresolved risk
9. Owner
10. Next evidence or action

## Design Critique

Critique the work, not the designer.

Ask:
- What outcome is this trying to create?
- Which user / context?
- Which constraints?
- Which decision is open for feedback?
- What evidence supports the current direction?

Feedback categories:
- critical user/product risk
- interaction/system issue
- visual craft
- open question
- personal preference

Do not present taste as requirement.

## Workshop Selection

### Problem framing
Use when the team disagrees about what problem it is solving.

### Assumption mapping
Use when the proposed solution is expensive and evidence is weak.

### Opportunity mapping
Use when many pains/features compete.

### Design studio
Use when the problem is framed but solution space is narrow.

### Pre-mortem
Use before high-risk launch:
"Imagine this failed badly. Why?"

## Workshop Closure

End with:
- decisions
- owners
- unresolved questions
- evidence needed
- date / condition for revisiting

A workshop that ends only with artifacts did not align the team.

## Handoff

Include:
- user / outcome
- flow
- design states
- permission behavior
- analytics events
- accessibility acceptance criteria
- responsive behavior
- error / async behavior
- open questions
- implementation constraints
- design-system additions
- feature flag / rollout notes

Do not hand off pixels without behavior.

## Launch Readiness

Check:
- implementation fidelity
- analytics
- permissions
- localization
- accessibility
- support readiness
- failure / recovery paths
- legal/privacy copy
- feature flag / rollback
- release communication where needed

## Post-Launch Review

Compare:
- expected behavior
- actual behavior
- segment differences
- guardrails
- support evidence
- qualitative feedback
- technical incidents

Decide:
- keep
- iterate
- expand rollout
- investigate
- revert
- deprecate
